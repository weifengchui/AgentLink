# v0.5 收官验证记录（2026-10-17 夜，v0.5.6 分支 feat/v0.5-wizard-hello）

范围：路线图最后两项——内核 `__node__` hello 自检 + 首跑 wizard / `agentlink hello` CLI。
本文记录实现口径、冒烟证据与一个新发现的连接层缺陷。

## 1. 实现口径

- **内核应答器**（router.rs）：保留 agent `__node__`（`HELLO_AGENT`）。`handle_incoming`
  在 lockdown 熔断**之前**拦截 `action=hello, to_agent=__node__` 的业务帧（type=text，
  与节点握手 ctrl/hello 以 type 区分，协议 §3.1）：dedup→seen→record_history→
  `hello_reply()` 自动应答。应答走正常 `send()`（继承 strict 签名/trace/history）；
  `action=hello_reply, from_agent=__node__` 的回程帧由内核同一分支消费，不进任何 agent
  inbox / local_pending。本机自探针直接回环记账；远端分支 `Box::pin(send())` 断
  `send→handle_incoming→hello_reply→send` 的 async 递归（E0733）。
  熔断开启时 hello_reply 属业务帧会被拦——CLI 会提示"超时属预期"，诊断面在熔断期照常记账。
- **应答 payload**：`node_id/name/version/protocol/uptime_seconds/probe`（探针回显）。
- **CLI `agentlink hello`**（cli.rs）：纯 local API 消费者——向本机+peers 快照各发一探针，
  轮询 /v1/events 至全命中或超时。`--node`（可重复，id 前缀≥4 位或名称）、`--timeout`
  （默认 10s）、`--json`（stdout 纯 JSON，摘要走 stderr，退出码 0=全通）、`--no-self`。
- **CLI `agentlink setup`**（wizard.rs）：交互向导（角色/名称/端口/集群令牌/安全模式→
  写配置→可选立即启动）；裸 `agentlink` 无配置且 TTY 时自动进入（Windows 双击 exe 旅程）；
  非 TTY 绝不交互，明确报错指路 init/join；`--yes` 非交互写默认配置。全程复用
  `generate_preserving_identity`——node_id/data_dir/local token 永不重置（2026-10-13 教训）。

## 3. 新发现缺陷：static_peers 互相 dial 导致连接层 flap（冒烟中暴露并修复）

现象：发 `__node__` hello 探针后 peer 连接 0.5–3.5s 周期性 online→offline。

根因：`conn.rs handle_text` 以 `action` 分派，`"hello"` 臂无条件按节点握手帧解析。
业务 hello 探针帧同为 `action=hello`（type=text），`from_value::<Hello>` 失败 →
旧代码 `return false` 断链，探针从未到达对端 router。

修复（本分支已含）：握手臂加守卫 `"hello" if value.get("auth").is_some()`
（Hello 必带 auth/nonce，Envelope 无），业务探针落入底部业务分支交 router 拦截；
握手帧畸形时改为忽略而非断链。修复后 run7 全绿。

遗留（未修，进 v0.5.x 待发）：两端 config 互相写 static_peers（A→B 且 B→A）时，
同一 node pair 存在双向两条 WS，conn 的去重表现为周期性 flap（与 hello 无关，
冒烟 run5 证实）。生产拓扑=星型单向 dial + UDP discovery，暂不受影响；
文档口径：**static_peers 只配单向（worker→master），不要互配**。
