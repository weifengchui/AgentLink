# 消息护栏验证（2026-10-20，v0.7 §4.3）

路线图 v0.7：「消息护栏中间件：PII / API Key / prompt-injection 特征过滤；
topic 默认 Deny All 作用域隔离」。

本包交付**发送路径护栏**：`/v1/send` 总线消息与 `/v1/tasks` 任务 spec 都会
按配置检测/脱敏/阻断；缺省 `security.guardrails.enabled=false`，不扫描、
不改写、不改变任何字节。

## 1. 配置

```jsonc
"security": {
  "guardrails": {
    "enabled": true,
    "action": "redact",          // redact（缺省）| block
    "pii": true,                 // 邮箱/手机/身份证/银行卡
    "secrets": true,             // OpenAI/AWS/GitHub/Slack key、Bearer、私钥块
    "injection": true,           // 中英文提示注入话术
    "topics": { "enabled": true, "allow": ["chat", "task_result"] }
  }
}
```

- `action="redact"`：命中片段替换为 `[REDACTED:<category>]`，消息/任务继续；
- `action="block"`：任一命中 → **422**（错误体只回类别，不回显原文）；
- `topics.enabled=true`：`payload.topic` 必须命中 `allow`；缺失/越界一律 422
  `topic_not_allowed`（不可脱敏）。`allow=[]` 即 Deny All。
- 任务 spec 没有 `payload.topic`，只做内容扫描、跳过 topic 门。
- `redact` 不区分大小写/嵌套：逐层遍历 payload 的所有字符串值（键名不扫）。

## 2. 检测规则（启发式）

| 类别 | 例子 | 占位符 |
|---|---|---|
| `email` | `alice@example.com` | `[REDACTED:email]` |
| `phone` | 中国大陆 `13812345678` | `[REDACTED:phone]` |
| `id` | 18 位身份证样式 `11010519491231002X` | `[REDACTED:id]` |
| `card` | 13-19 位且通过 Luhn 校验的卡号 | `[REDACTED:card]` |
| `secret` | `sk-…` / `AKIA…` / `ghp_…` / `xox…` / `Bearer …` / PEM 私钥块 | `[REDACTED:secret]` |
| `injection` | `ignore all previous instructions` / `系统提示词` / `你现在是` 等 | `[REDACTED:injection]` |

卡号先按分组正则匹配，再用 Luhn 过滤，避免把普通长数字全部误伤。

## 3. 生效路径与可观测性

```
POST /v1/send   ──► guardrails::inspect（含 topic 门）──► 投递/422
POST /v1/tasks  ──► guardrails::inspect_with_topics(false) ──► 入表/422
```

- `block`：审计 `guardrail.blocked`（含 `source=send|task`、`findings`、topic，
  **不含原文**）+ webhook `guardrail_alert`（`kind=blocked`）。
- `redact`：审计 `guardrail.redacted`（含类别计数），投递/入库的是脱敏副本。
- `GET /v1/status.guardrails` 暴露 `{enabled, action, pii, secrets, injection,
  topics_enabled}`。
- 仅在**本地 API 入口**扫描；已经进入总线的帧、节点间转发、引擎内部
  `task_spec` 重投不二次扫描（避免重复改写与延迟放大）。

## 6. 边界与残留

1. **启发式而非 DLP**：编码/拆分/同义改写可绕过；不检测图片、文件内容、
   语音；正则误报（如测试数据里的示例邮箱）会按配置脱敏/阻断。
2. **只扫字符串值**：payload 键名、agent id、文件路径/文件名不扫；非字符串
   标量不扫。
3. **入口扫描**：直接经 peer 协议进来的帧、GitOps 目录任务、引擎重投的
   `task_spec` 不重复扫描；GitOps 任务因此绕过了 `/v1/tasks` 护栏。多节点
   部署应在每个入口节点开启护栏。
4. **topic 白名单是节点级全局**：不按 agent/namespace 细分；启用前要确认
   所有业务 topic（含唤醒、回信、自定义协议）都在 `allow` 里。
5. **脱敏不可逆**：history/journal/引擎表存的是占位符副本，没有原文映射，
   无法事后还原；`block` 模式更适合强合规场景。
6. **block 的反馈只有类别**：错误体/webhook 不含原文（防二次泄露）；排障
   需结合发送方自己的日志。
7. **性能**：大 payload 会跑多条正则；建议配合请求体大小限制与入口限流。
