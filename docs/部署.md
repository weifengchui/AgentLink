# AgentLink 部署指南

## 0. 构建与交叉编译

本机原生构建：

```bash
cargo build --release
# 产物 target/release/agentlink（Linux/macOS）或 target\release\agentlink.exe（Windows）
# release 约 1.5–1.8 MB（LTO + strip + opt-level=z）
```

交叉编译（在 Linux 上出 Windows 可执行文件）：

```bash
# 需要 mingw-w64：apt install gcc-mingw-w64-x86-64
rustup target add x86_64-pc-windows-gnu
cargo build --release --target x86_64-pc-windows-gnu
# 产物 target/x86_64-pc-windows-gnu/release/agentlink.exe
```

### 免 root 交叉编译（WSL 无 sudo 时的实测方案：llvm-mingw）

已在 WSL（Ubuntu 24.04，无 sudo）上验证可用：

```bash
rustup target add x86_64-pc-windows-gnu

# 1) 下载 llvm-mingw（含 import 库与 dlltool）
#    https://github.com/mstorsjo/llvm-mingw/releases （选 msvcrt + ubuntu + x86_64 的 tar.xz）
#    解压到 /opt/llvm-mingw（或任意目录，无需 root）

# 2) llvm-mingw 无 libgcc：放两个占位/替代库到其 x86_64-w64-mingw32/lib 下
cd <llvm-mingw>/x86_64-w64-mingw32/lib
: > empty.o && <llvm-mingw>/bin/llvm-ar rcs libgcc.a empty.o    # 占位
cp -f libunwind.a libgcc_eh.a                                   # 真实 unwinder（提供 SEH/_Unwind_*）

# 3) 构建
export PATH="<llvm-mingw>/bin:$PATH"
CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER=<llvm-mingw>/bin/x86_64-w64-mingw32-gcc \
CARGO_TARGET_X86_64_PC_WINDOWS_GNU_RUSTFLAGS="-Lnative=<llvm-mingw>/x86_64-w64-mingw32/lib" \
cargo build --release --target x86_64-pc-windows-gnu
# 产物：target/x86_64-pc-windows-gnu/release/agentlink.exe（约 1.8 MB）
```

mDNS 需要编译期特性（可选）：

```bash
cargo build --release --features mdns
```

## 1. 单机快速上手（不装服务，前台跑）

**方式一（推荐，v0.5.6 起）**：直接双击 `agentlink.exe` 或在终端敲裸 `agentlink`——检测到无配置且是交互终端时自动进入首跑向导，按提示选角色（新建/加入集群）、名称、端口、安全模式，写完配置可选立即启动。非交互环境（systemd/管道/脚本）不会进向导，行为与旧版一致。

```bash
agentlink setup          # 显式启动向导
agentlink setup --yes    # 非交互写默认配置（端口 8765、strict、自动 node_id）
```

**方式二（原手动路径）**：

```bash
agentlink init --name agent-PC-A     # 生成 agentlink.json（随机 node_id / token）
agentlink run
curl http://127.0.0.1:8765/v1/health
```

**组好后一条命令自检全网**（v0.5.6 起，内核内置 `__node__` 应答器）：

```bash
agentlink hello            # 遍历本机+所有已知对端，输出聚合应答表（版本/RTT/uptime）
agentlink hello --json     # 机读输出（纯 JSON，成败看退出码：0=全通）
agentlink hello --no-self  # 只探对端；--node <id前缀|名称> 可重复指定目标
```

探帧发往保留 agent `__node__`，由内核直接应答（版本/协议/uptime/node_id/探针回显），不投递到任何本地 agent、不进 inbox，strict 签名与 history 审计照常记账。

## 2. Windows

### 2a. 桌面/免服务方式（推荐，v0.4.9 起自启内置）

1. 解压发布包到任意目录（如 `E:\Tools\AgentLink-vX.Y.Z\`），双击 `启动.bat`：
   - 无配置时自动 `init`；已运行（8765 占用）则提示不重复启动。
   - 顺带静默注册当前用户的开机自启（`agentlink autostart`：在
     `%APPDATA%\...\Start Menu\Programs\Startup\AgentLink.vbs` 写入隐藏窗口启动脚本，
     **无需管理员权限**；`schtasks /SC ONLOGON` 需要提权，故不用它）。
     重启/重新登录后节点以 `run --no-open` 静默拉起，不弹浏览器。
2. 管理自启：
   ```powershell
   .\agentlink.exe autostart            # 查看/注册（幂等）
   .\agentlink.exe autostart --force    # 升级换目录后按当前路径重注册
   .\agentlink.exe autostart --remove   # 取消自启
   wscript "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\AgentLink.vbs"  # 立即启动一次
   ```

### 2b. 服务模式（可选，需管理员）

1. 把 `agentlink.exe` 放到任意目录（如 `C:\tools\agentlink\`）。
2. 管理员 PowerShell 执行：`.\deploy\install-windows.ps1 -Binary C:\tools\agentlink\agentlink.exe`
   - 自动生成配置、注册 Windows 服务（开机自启）、放行防火墙 TCP 8765 / UDP 8766。
3. 若要重新生成身份：删除配置后重跑或手动编辑。

常用命令：

```powershell
Get-Service agentlink
Restart-Service agentlink
sc.exe delete agentlink   # 卸载服务（不删二进制）
```

## 3. Linux（systemd）

```bash
sudo ./deploy/install-systemd.sh
sudo systemctl enable --now agentlink

```

```bash
      /Library/LaunchDaemons/com.agentlink.plist
sudo launchctl load -w /Library/LaunchDaemons/com.agentlink.plist
```

## 5. 多机组网（同一局域网）

每台机器只跑一个 Node：

```bash
# 主机
agentlink init --name agent-PC-A
# 新机器：从主机的 init 输出复制这串 → 一键配对（无需手改 json）
agentlink join <token> --name agent-PC-B
# 或者内网快速测试用免密：
#   agentlink init --open  /  agentlink join <token> --open
```

`agentlink run`（或装成服务）。防火墙放行：TCP `8765`、UDP `8766`（不同网卡/子网时，广播可能不通，见下）。

> `strict` 模式下 node 之间的共享密钥是 `agentlink join <token>` 自动写入的；
> `--open` 跳过校验，仅用于隔离/调试网络。

验证某台机器能看到其他节点：

```bash
curl -H "X-Auth-Token: <本地 token>" http://127.0.0.1:8765/v1/peers
```

### 广播被禁/跨网段的兜底

在 `agentlink.json` 里写死对端地址：

```jsonc
"discovery": {
  "methods": ["udp_broadcast", "mdns"],
  "static_peers": ["192.168.1.11:8765", "192.168.1.12:8765"]
}
```

> 静态对等只会**主动拨号**；为避免双向重复连接，建议只在其中一台机器上配置 `static_peers`，或尽量用 discovery。mDNS 需 `--features mdns` 编译并加入 `methods`。

## 6. 防火墙速查

| 协议 | 端口 | 用途 |
|------|------|------|
| TCP | 8765 | Peer WebSocket（消息 + 文件）、本地 API |
| UDP | 8766 | 节点发现广播 |

## 7. 数据目录（v0.4.10 起默认外置）

节点的所有运行数据（接收文件 `files/`、`uploads/`、历史 `history.jsonl`）都放在
`data_dir` 指向的目录。**不要把数据目录放进软件目录**——升级通常是整目录替换
（`AgentLink-vX.Y.Z`），数据放软件里容易被覆盖或随版本目录被弃用。

- 默认值（配置里不写 `data_dir` 时）：
  - Windows：`%LOCALAPPDATA%\AgentLink\data`
  - Linux：`$XDG_DATA_HOME/agentlink` 或 `~/.local/share/agentlink`
- 每台机器可以在 `agentlink.json` 里写各自的 `data_dir` 绝对路径，互不影响。
- 相对路径一律以**配置文件所在目录**为基准解析（与进程当前工作目录无关，
  开机脚本从 system32 拉起也不会跑偏）。
- 收文件子目录 `files.recv_dir` 不设时跟随 `<data_dir>/files`。

迁移旧数据（软件目录里有 `./data`）：停节点 → 把整个 `data` 目录移到目标位置 →
配置里写 `data_dir` 绝对路径 → 起节点 → `/v1/status` 确认 peers/文件正常。

### 7.1 队列与历史持久化（v0.4.12 起）

- `data_dir/journal.jsonl`：消息队列（inbox/offline/pending/local/seen）的追加日志，
  每条 fsync；重启按 add/del 全量回放，离线队列中已过 TTL 的条目回放时直接丢弃。
- `data_dir/agents.json`：本机 agent 注册表的原子快照，硬 kill 也不丢，重启自动恢复。
- `data_dir/history.jsonl`：会话历史重启回放进内存环形缓冲；超过 `history.max_file_mb`
  （默认 16）轮转为 `history.jsonl.1`；`history.file` 置空串可关闭。
- 开关：`delivery.persist=false` 停用 journal（一次性/测试节点专用，重启即丢在途消息）；
  `delivery.agent_stale_ttl_seconds`（默认 3600）自动清理长期离线未重注册的 agent，0 关闭。
- 冒烟验证：`python3 tests/persistence_smoke.py`（隔离端口 18765，SIGKILL 重启断言 14 项）。

## 8. 升级

协议帧带 `v` 版本；升级仅替换二进制并 `Restart`/`restart` 服务即可，新旧节点可混跑（沿用同一 `agentlink.json` 与 token）。
v0.4.12 起数据目录新增 `journal.jsonl`/`agents.json`/`history.jsonl`，均随 `data_dir` 走、不在升级包内，替换 exe 即完成升级，队列在重启时自动回放。

v0.4.13 修 `/v1/send-file-upload` 的体上限：此前该路由没设 `DefaultBodyLimit`，被 axum 默认 2 MiB 卡住，
配置里的 `files.max_file_size`（默认 100 MB）形同虚设——界面发超过 2 MiB 的文件会失败且报错难读。
升级后上限真正跟随 `max_file_size`（在进程启动时读取，改配置需重启生效），超限返回 JSON
`file too large: N bytes (limit M)`。回归测试：`tests/upload_limit_smoke.py`（隔离端口 18765，6 项）。

## 9. 多 Agent 运维组织建议（3 机以上）

3 机以上、或需要统管"升级 / 切模型供应商"时，推荐按以下角色分工组织：

- 角色分层：人类决策 → 协调 agent（政策发布 / 发令 / 裁决 / 验收）→ 每机 1 个运维 agent（模板名 `ops`）→ worker×N。
- 三类运维流程：滚动升级（期望版本+调谐+失败保旧+金丝雀+sha 台账）、切模型（切换前先清点守卫/保活任务；回滚=改一个字段重跑切换器）、健康巡检（先脚本化再谈角色分工）。
- 规模建议：1-2 机一人兼任 / 3-10 机标准形态（含最小 3 机样例）/ 10-100 机专职运维节点+树状分域+GitOps。
- 寻址硬约束：`to=node_id` + `to_agent` 成对给；agent_id 严格用 profile 名不加 IP 后缀；跨机同名是特性，靠 node_id 区分。

## v0.4.14（2026-10-15）界面与错误可见性

- 网页标题与顶栏显示当前版本（`AgentLink · Console v0.4.14` / `v0.4.14` 徽标），一眼确认在跑哪个包。
- 修「点发送文件后文件消失、对话记录没新内容」：`j()` 此前把非 JSON 的 HTTP 错误兜底成 `{}`，
  于是 413/400/HTML 错误页被当成成功——清空了 file input 却不产生任何记录。现在 `j()` 检查
  `r.ok`，非 2xx 抛出 `HTTP <code> <error>`，界面如实显示「发送失败: …」。
- 发消息与发文件合并为**一个「发送」按钮**：正文与附件可同时给，先发文本再传附件，
  结果一行汇总（`消息 ok · 附件 ok #file_id`）；只有附件或只有文本都能发。
- 附件支持三种来源：点「选文件」、在输入框 **Ctrl+V 直接贴图**（自动命名
  `image-YYYYMMDDHHMMSS.png`）、以及**拖拽文件到虚线投递区**。
- **支持发送目录**：拖入文件夹或点「选目录」，浏览器端把目录下所有文件（含子目录）
  打包成 `<目录名>.zip`（store 不压缩、UTF-8 文件名）再作为单个附件上传。
  ZIP 由 `zipStore()` 生成，CRC32 已用 Python `zipfile.testzip()` 校验通过。
- 上传体上限沿用 v0.4.13 的修复（跟随 `files.max_file_size`），实测 3 MiB 附件端到端可达。
