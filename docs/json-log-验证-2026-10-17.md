## 1. 日志格式开关

两条途径，以现有配置体系为主：

- **配置文件** `agentlink.json`：`"log": { "format": "json" }`（`text` 为默认，等价于不写）。
- **CLI 全局参数**：`agentlink --log-format json`（覆盖配置文件，只影响本次启动，不回写配置）。

实现位置：`src/logging.rs`（基线已有 json layer 切换）+ `src/main.rs`（`--log-format`
global 参数，在 `logging::init(&cfg.log)` 前覆盖 `cfg.log.format`）。

### 向后兼容（红线）

默认 `format=text` 且默认 `level=info` 时，**输出与基线逐字节一致**。
所有新增结构化事件一律定在 **DEBUG** 级：info 级下被 env-filter 抑制，现舰队
（依赖现有文本行做解析/告警）零感知。要看结构化生命周期事件需 `level=debug`
（JSON 或 text 均可；JSON 下字段齐备，text 下为 k=v 内联）。

JSON 模式下使用 `json.format = "compact"` 时一行一事件，适合 `grep | jq`；
默认 pretty 多行，jq 需 `jq -s`。

## 2. trace_id 策略：**注入帧 metadata**（未降级为纯映射表）

协议兼容性论证：信封 HMAC 输入是 `from|msg_id|ts` 三段（`src/proto.rs`），
**不含其余字段**；`trace_id` 作为 serde 可选字段追加进 Envelope
（`#[serde(default, skip_serializing_if)]`），旧节点反序列化时按 unknown/缺省字段
忽略，验签与路由不受影响。冒烟 S3f 在 `security.mode=strict` 双节点总线上实测
注入后零 reject。

解析优先级（`src/trace.rs::resolve_and_remember`）：

1. 入站帧已带非空 `trace_id` → **沿用**（agent echo / 上游注入）；
2. 帧是 `reply_to` 回复且本节点 `TraceMap` 存有 parent msg_id → **续接 parent 的 trace**；
3. 否则内核生成：`t-` + `msg_id` 前 8 位（确定性、免 uuid crate、可读）。

解析结果在 `Router::trace_for` 注入 `env.trace_id`（发送签名前 / 入站验签后），
转发与投递帧随之携带，**下游 agent 天然续链**。

内核侧 `Router.trace_map: Mutex<TraceMap>`（有界 8192，插入序驱逐）是策略 2 的
支撑：agent 回报不 echo 时靠 `reply_to → msg_id` 查表续链。map miss 只退化为
派生新 trace，绝不丢数据。

## 3. 结构化事件清单（`src/router.rs` 等）

每条固定字段：`trace_id, correlation_id, msg_id, from, to, from_agent,
to_agent, node_id, topic`；无消息上下文的运维事件字段值取 `"-"`。
`correlation_id`/`topic` 从 payload 的 `correlation`/`topic` 提取（任务协议字段）。

| 事件（JSON `fields.message`） | 级别 | 触发点 |
|---|---|---|
| `al.message.send` | DEBUG | 本节点发出（含广播） |
| `al.message.forward` | DEBUG | 经 peer 通道转发成功 |
| `al.message.incoming` | DEBUG | 入站验签通过 |
| `al.message.deliver` | DEBUG | 投递给本地 WS 订阅者 |
| `al.message.inbox` | DEBUG | 无在线订阅者，暂存 inbox |
| `al.message.reject` | DEBUG | 入站验签/时间窗失败（伴随原 warn） |
| `al.message.defer` | DEBUG | 目标离线，入离线队列 |
| `al.message.fail` | DEBUG | 重试用尽投递失败 |
| `al.history.persist` | DEBUG | history.jsonl 落盘（direction/seq） |
| `al.peer.up` / `al.peer.down` | DEBUG | peer 注册/注销（原 info 文本行保留） |
| `al.agent.register` / `al.agent.unregister` | DEBUG | agent 注册变更 |

`HistoryEntry` 同步新增可选 `trace_id`（serde default，旧行可读）。

## 8. 取舍与已知边界

- **生命周期事件定级 DEBUG**：换取默认 info 级文本输出零变化（红线优先于便利）；
  JSON 用户需 `log.level=debug` 才能看到 al.* 事件流。
- **TraceMap 有界 8192**：超长存续任务的 reply_to 续链可能 miss，退化为新 trace
  （agent echo 不受此限——注入策略保证帧上始终有 trace）。
- **ack/journal 控制帧不带 trace**（kind=ack 走 peer 通道，非业务信封）。
- 旧节点发给新节点：无 trace 字段 → 规则 2/3 兜底；新→旧：旧节点 serde 忽略
  `trace_id` 正常路由投递（agent 侧 JSON 解包会看到多一个字段，属 additive）。
