# CLI 薄壳验证记录 — 2026-10-17（分支 `feat/cli-shell`）

## 定位

v0.5 路线图的 `agentlink` CLI 薄壳：`get / logs / apply` 三族子命令是**纯 REST wrapper**——
不启动节点、不读写本地总线存储，只调用本机 local API（`GET /v1/*`、`POST /v1/send`，
鉴权头 `X-Auth-Token: *** local_api.token`）。内核零改动，`api.rs` 路由表原样消费。

对应正本：`docs/task-protocol.md` §1/§2（task_spec 形状与消息类别）、
`docs/v0.5-内核待发清单.md` §1（/v1/events）、§3（/v1/fleet/agents?requires）、§4（/v1/tasks）。

## 寻址与鉴权解析

- 全局 `--url`：默认 `http://127.0.0.1:<--config 指定配置的 listen_port>`。
- 全局 `--token`：默认读 `--config` 指定 `agentlink.json` 的 `local_api.token`。
- 两者同时给出时**完全不读配置文件**；需要配置而文件缺失时报错提示
  `run \`agentlink init\``（复用 main.rs `load_config` 的友好错误路径）。

## 命令面

```
agentlink [--config F] [--url U] [--token T] <COMMAND>

get nodes                      # /v1/health + /v1/peers 汇总：name/node_id/address/在线/版本
get agents [--requires cap:a,b] [--online]   # /v1/fleet/agents；--requires 服务端原生过滤，
                                             # --online 客户端过滤；列 agent_id/name/capabilities/在线/node
get tasks [--correlation C] [--state s1,s2]  # /v1/tasks；列 task_id/type/state/target/from/corr/last_ts
logs [--agent A] [--types text,file] [--limit N] [--since SEQ] [--follow]
                               # /v1/events（脱敏件，如实打印）；逐行 #seq ts [方向] 节点/agent → 节点/agent kind 摘要
                               # --follow：next_seq 增量轮询，空轮 500ms 基线、命中提速 200ms，
                               #           环轮换(409)时从 oldest_seq 续读，Ctrl-C 干净退出(rc=0)
apply -f task.json --to-agent W [--to NODE] [--from-agent cli] [--dry-run]
                               # 文件=协议 §2 task_spec JSON（缺 topic/task_id/seq 自动补全，
                               #   task_id 用 uuid v4）；POST /v1/send（type=text, action=send，
                               #   from/to 默认取 /v1/health 的 node_id）；实发打印 msg_id/ack，
                               #   --dry-run 只打印请求体不发送
```

列说明（与派发文案的偏差）：内核 `TaskView` 投影无独立节点列，故 `get tasks` 的
`target`=to_agent、`from`=from_agent、另设 `corr`=correlation；`/v1/peers` 帧不含对端
版本，`get nodes` 版本列本机取自 `/v1/health`、对端以 `-` 如实呈现。

## 依赖新增

- `reqwest 0.12`，`default-features = false, features = ["json", "rustls-tls"]`。
  纯 Rust TLS 栈（禁 native-tls/openssl），保持 `x86_64-pc-windows-gnu` 交叉编译友好。
  带进 hyper-util/tower-http/rustls 等传递依赖，release 体积 Linux ~5.3MB（原 ~3.0MB）。
- 复用既有依赖：`clap`（子命令）、`serde_json`、`uuid`（apply 补 task_id）、`tokio` signal（Ctrl-C）。

## 已知边界

- 薄壳只读本机节点视图：`get nodes/agents/tasks` 打的是被查询节点自己的 local API，
  跨机汇总需对每台节点分别 --url。
- `/v1/send` 的 bus ack 只到帧级；apply 打印的 msg_id/ack 是路由受理件，任务终态以
  `get tasks --correlation` 为准（协议 §3：执行方是唯一状态权威）。
- follow 的 409 续读起点是 oldest_seq（薄壳不重建全史），若关心掉出环的旧事件请用
  `/v1/history`（未在本轮包装）。
