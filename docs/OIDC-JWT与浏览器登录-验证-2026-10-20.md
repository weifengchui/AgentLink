# OIDC 第二波：RS256/JWKS 本地验签 + 浏览器登录（2026-10-20，v0.7.1 候选）

第一波（`docs/OIDC-SSO-验证-2026-10-20.md`）只做 RFC 7662 introspection：
未知 token 每次都要打 IdP，且没有浏览器登录。本包补齐企业部署最常用的
两条路径：

1. **RS256 JWT 本地验签**：公钥来自 `jwks_uri`，缓存后 API 请求不再打 IdP；
2. **Authorization Code + PKCE 浏览器登录**：Web 控制台点「企业 SSO 登录」，
   回调后由 AgentLink 签发本节点短期 opaque session token，IdP 的
   access/ID token 不进入浏览器存储。

仍然保持：单二进制、纯 Rust 依赖（`rsa`/`sha2`/`base64`/`rand`，无 C /
openssl）、`auth.oidc.enabled=false` 时旧配置与静态 token 行为不变。

## 1. 验证模式

`auth.oidc.mode` 三选一，缺省 `introspection`：

| mode | API token 路径 | 适用 |
|---|---|---|
| `introspection` | 只走 RFC 7662；兼容 opaque / JWT access token | 第一波行为，零变化 |
| `jwt` | 只做 RS256/JWKS 本地验签；opaque token 401 | IdP 签发 JWT access token、要求离线可用 |
| `hybrid` | 先本地验签；非 JWT 或验签失败再 introspection | 迁移期；JWT 成功时 0 次自省 |

- `jwt`/`hybrid`/`browser_login` 需要 `issuer` + `jwks_uri`；
- `introspection`/`hybrid` 需要 `introspection_url` + `client_secret`；
- `jwt` 可以没有 `client_secret`、没有 introspection 配置；
- `browser_login` 需要 `authorization_endpoint` / `token_endpoint` /
  `redirect_uri`；public client + PKCE 时 `client_secret` 可为空。
- JWT `aud` 缺省校验 `client_id`；IdP 的 access token audience 不同时用
  `audience` 覆盖（ID token 通常仍是 client_id）。

## 2. 配置

```jsonc
"auth": {
  "oidc": {
    "enabled": true,
    "mode": "hybrid",                    // introspection | jwt | hybrid
    "introspection_url": "https://idp.example.com/oauth2/introspect",
    "client_id": "agentlink",
    "client_secret": "********",         // jwt 模式可省；public PKCE 可省
    "audience": null,                    // 可选；缺省=client_id
    "issuer": "https://idp.example.com",
    "jwks_uri": "https://idp.example.com/oauth2/jwks",
    "jwks_cache_seconds": 3600,          // 1-86400
    "leeway_seconds": 60,                // 0-300
    "role_claim": "groups",
    "role_map": {
      "agentlink-admins": "admin",
      "agentlink-ops": "operator",
      "agentlink-viewers": "viewer"
    },
    "default_role": null,
    "namespace_claim": "namespace",
    "cache_seconds": 30,                 // 1-3600
    "timeout_seconds": 3,                // 1-30

    "browser_login": true,
    "authorization_endpoint": "https://idp.example.com/oauth2/authorize",
    "token_endpoint": "https://idp.example.com/oauth2/token",
    "redirect_uri": "https://agentlink.example.com/v1/auth/oidc/callback",
    "post_login_path": "/web",
    "scopes": "openid profile email",
    "session_seconds": 28800              // 1-86400；且不超过 ID token exp
  }
}
```

传输安全：所有 IdP URL 生产必须 `https://`；仅
`127.0.0.1` / `localhost` / `[::1]` 允许 `http://`。`redirect_uri` 若用
`http://` 也只能回环，且不能带 fragment。`post_login_path` 必须是站内绝对
路径（以 `/` 开头、不是 `//host`、无 `#`/空白/控制字符）。

## 3. 浏览器登录流程

```
GET /v1/auth/oidc/login
  ├─ 生成 state / nonce / PKCE verifier（S256）
  ├─ state 存本节点 LoginStore（5 分钟、一次性、最多 1024）
  ├─ Set-Cookie: al_oidc_state=<state>; Path=/v1/auth/oidc/callback;
  │              HttpOnly; SameSite=Lax; Max-Age=300[; Secure]
  └─ 307 到 authorization_endpoint?response_type=code&...&code_challenge=...

IdP 登录/授权
  └─ 302 redirect_uri?code=...&state=...

GET /v1/auth/oidc/callback?code&state（公开路径）
  ├─ 校验 Cookie al_oidc_state == query.state（防登录 CSRF）
  ├─ 取出并删除 state；过期/重放 -> 400
  ├─ POST token_endpoint：code + redirect_uri + code_verifier
  │    client_secret 非空 -> Basic；为空 -> public client + PKCE
  ├─ RS256 本地验签 ID token：iss/aud/azp/exp/nbf/iat/nonce
  ├─ claim -> 角色/namespace（与 introspection 完全同口径）
  ├─ 签发 al_sess_<32B random> 本节点 session
  │    TTL = min(session_seconds, ID token exp - now)
  └─ 303 /web#token=al_sess_...（no-store / no-referrer）
```

Web UI 在 `boot()` 里只从 URL fragment 取一次 token，写入
`sessionStorage`，随后 `history.replaceState` 抹掉 fragment；后续请求继续用
`X-Auth-Token`。fragment 不会发给服务端/Referer，也不进入代理访问日志。

## 4. JWT 本地验签

- 只接受 `alg=RS256`；拒绝 `none` / `HS*` / `PS*` / `ES*`，不做算法降级。
- JWT header `kid` 选 key；无 `kid` 时只有 JWKS 唯一 key 才接受。
- JWKS 缓存 `jwks_cache_seconds`；过期或未知 `kid` 触发刷新。刷新尝试 2s
  节流，避免伪造 `kid` 打爆 IdP。拉取/解析失败 fail-closed。
- RSA 模长 < 2048 bit 的 key 直接跳过；JWKS 中 EC/加密 key 忽略。
- 校验：`iss` 精确匹配、`aud` 含期望 audience、`azp`（若有）等于
  `client_id`、`exp`/`nbf`/`iat` + leeway、浏览器 ID token 的 `nonce`。
- 成功后按 token sha256 缓存；JWT 缓存 TTL 不超过 `exp`。
- `jwt` 模式不可用 opaque token；`hybrid` 的 JWT 失败会回落 introspection，
  仍由 IdP 决定是否 active，不会因为本地验签失败而放行。

## 5. 角色 / 多租户 / WS

- 角色/namespace 解析复用第一波：`role_claim` 字符串或数组、`role_map`
  精确匹配、`default_role` 不得 Admin、`namespace_claim` 非 Admin 必填、
  Admin 必须全局且不得绑定。
- 静态 `auth.tokens` / `local_api.token` 仍最优先；浏览器 session 直接放行，
  不再走 introspection/JWT。
- 内部头 `x-agentlink-oidc-role` / `x-agentlink-oidc-namespace` 入口先剥除，
  只在验证成功后注入；客户端伪造无效。
- `/v1/ws`：
  - `local_api.token` 全局；
  - 静态绑定 token 仅本租户（既有）；
  - 浏览器 session：Admin 全局，非 Admin 仅绑定 namespace；
  - IdP 的 access/ID token **仍不支持** WS（避免长连接 URL 写 access token）。

## 6. 端点

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/v1/auth/oidc/status` | 公开 | `{enabled,browser_login,mode}`，Web 决定是否显示 SSO |
| GET | `/v1/auth/oidc/login` | 公开 | 307 到 IdP，设置 state cookie |
| GET | `/v1/auth/oidc/callback` | 公开 | code/PKCE 换 token，303 回 Web |
| POST | `/v1/auth/logout` | 需 token | 删除本节点 session；静态 token no-op |
| GET | `/v1/ws?token=al_sess_...` | session | 浏览器 session 订阅 |

`/v1/health`、`/web`、`/v1/web`、`/v1/starmap`、`/web/setup`、`/v1/ws`、
`/peer/*` 以及 OIDC login/callback 不触发 API token 校验。

## 8. 边界与残留

> 第三波已补齐：多算法白名单（ES256/PS256/EdDSA）、`at_hash`/`c_hash`、
> `response_mode=form_post`、RP-initiated logout、refresh token 续期——
> 见 `docs/OIDC-兼容硬化-验证-2026-10-20.md`。下面第 1/5/6/7/13 条已在
> 第三波闭合。

1. **只支持 RS256**：ES256/PS256/EdDSA 未接；多算法需要引入对应纯 Rust
   实现与算法白名单，不在本包范围。
2. **JWKS 故障 fail-closed**：缓存过期且拉取失败时新 JWT 全部 401；已缓存
   key 在 TTL 内可用。没有“过期后 stale key 继续用”的逃生门。
3. **吊销延迟**：JWT 本地验签只认 `exp`，IdP 提前吊销需要等 `exp` 或
   `cache_seconds` 缓存过期；对高敏感部署建议短 `cache_seconds`。
4. **浏览器 session/state 都是本节点内存态**：重启/多节点不共享；多副本
   部署需要 login/callback 与后续请求都粘到同一节点，或后续接外部 state/
   session store。刷新页面 token 仍在 sessionStorage；关闭标签页即丢。
5. **没有 refresh token / RP-initiated logout**：session 到期或本地 logout
   后需重新走 IdP；不会调用 IdP 的 end_session_endpoint。`logout` 只删本
   节点 session。
6. **state cookie 绑定同 host**：login 与 callback 必须同 host（端口可不同）；
   跨域/多域名部署需要调整 cookie domain 或改用服务端浏览器会话。当前只支持
   `response_mode=query`（默认），未接 `form_post`。
7. **没有 at_hash/c_hash 校验**：Code Flow + PKCE 下非必需；高安全场景可
   在后续包补。
8. **IdP token 不进浏览器**：Web 只拿 AgentLink opaque session token；因此
   IdP 的 access token 不能直接用于第三方 API 调用。OIDC access token 仍
   不支持 `/v1/ws`。
9. **session 无服务端吊销列表广播**：logout 只影响当前节点；多节点各自
   session 独立。Admin 可在配置层关闭 `browser_login` 使新 session 失效
   （重启后旧 session 也清空）。
10. **角色 claim 仍要求 ID token 自带**：若 IdP 只把组信息放在 userinfo/
    access token，需要配置 IdP 把 claim 放进 ID token，或继续用
    introspection 模式。
11. **配置不热加载**：`auth.oidc` 变更需重启；`PUT /v1/config` 不触碰该段。
12. **登录入口无限流**：state store 有 1024 上限和 5 分钟 TTL，但公网部署
    仍建议在反向代理对 `/v1/auth/oidc/login` 做速率限制。
13. **只支持 query 回调**：不支持 `response_mode=form_post`；IdP 侧需使用
    默认 query 模式（或后续补 POST callback + SameSite=None cookie）。
