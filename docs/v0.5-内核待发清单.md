# v0.5 内核待发清单（协议先行，内核后置）

任务协议 v1（docs/task-protocol.md）已定稿并在隔离总线以纯 payload 层跑通全生命周期（docs/task-protocol-验证-2026-10-17.md）——**零内核改动**。本清单是内核侧的增项规格：v0.5.x 发版时按此实现，不改业务层协议。注意：当前 `src/` 有 web console 轮次的未提交工作（api.rs/store.rs/starmap.html），内核改动须等该轮收口后进。

## 1. `subscribe_events`（控制面事件流，P0）

现状：编排方轮询 `/v1/history`（参考实现即如此），事件语义完整但有轮询延迟。

- `GET /v1/events?since=<seq>&agent=<id>&types=<csv>`：按 append-only 序号增量返回**业务帧**（不含 ctrl/heartbeat），响应 `{events:[{seq,ts,frame}], next_seq}`。
- `since` 语义：返回 seq ≥ since 的事件；history 环满时回 409 + 最旧可用 seq（编排方降级全量 history 重建）。
- 帧内 payload 输出前过**脱敏管线**（§2）。
- 验收：参考 orchestrator 的 wait() 改走 /v1/events 后延迟 P50 < 500ms，重连不丢事件（since 续传）。

## 2. payload 脱敏（P0，商用审计前置）

- 配置 `redact.patterns`（正则列表）+ 内置默认集（token/password/private key 块/十六进制长串）。
- `/v1/history`、`/v1/events`、`/web` 输出路径统一走同一管线；**转发/投递给目标 agent 的帧不脱敏**（收件人拿原文，观察者拿脱敏件）。
- 验收：含 `X-Auth-Token: …` 文本的消息，history 查询返回 `<REDACTED:token>`，目标 WS 收到原文。

## 3. registry capabilities 查询与匹配（P1）

- `GET /v1/fleet/agents?requires=cap:a,cap:b`：返回能力满足的在线 agent（含 node 地址）。
- 能力字符串规范：`cap:<域>:<动作>` 层级冒号分隔，通配 `cap:node:*`。
- 调度器（AgentMesh 收费层）的准入控制直接消费此接口；开源版仅提供查询不做匹配调度。

## 4. `/v1/tasks` 资源视图（P2，内核可选）

把 task 消息轨迹投影成任务对象：`GET /v1/tasks?correlation=&state=`（从 history 派生，非独立存储——保持 append-only 单一事实源）。验收：smoke 场景跑完后 `GET /v1/tasks?correlation=batchX` 返回各任务终态。

## 5. 兼容与版本

全部为加性接口；`v` 协商沿用协议 v1 §7。上列任一项发布时，`/v1/health` 增加 `features:[...]` 数组供编排方探测降级。
