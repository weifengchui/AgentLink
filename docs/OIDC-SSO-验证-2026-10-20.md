# OIDC SSO 第一波验证（2026-10-20，v0.7 §4.2 企业门槛）

路线图 v0.7：「OIDC SSO（企业采购门槛，先做 SSO 不做 HSM/FIPS）」。

本包交付 **token introspection（RFC 7662）+ claim → RBAC 角色映射 + 可选
namespace 绑定**，把企业 IdP 接入现有静态 token/RBAC/多租户体系：

- 静态 token（`auth.tokens` / `local_api.token`）优先级最高，行为零变化；
- 未知 token 走 IdP introspection，成功才放行，失败一律 401（fail-closed）；
- 角色来自 `role_claim`（字符串或数组）+ `role_map`，不支持隐式 Admin；
- `namespace_claim` 开启后，非 Admin token 必须带合法 namespace，Admin 必须
  全局（不可绑定），复用 §4.2 的任务/agent 隔离；
- 成功结果按 token sha256 缓存 `cache_seconds`，避免每请求打 IdP。

不做 JWT 本地验签（避免引入 RSA/ring 等依赖与算法矩阵），也不做浏览器
OIDC 登录流/WS 订阅——见残留。

## 1. 配置

```jsonc
"auth": {
  "tokens": { "legacy-op": "operator" },        // 静态 token 继续有效
  "token_namespaces": { "legacy-team": "team-a" },
  "oidc": {
    "enabled": true,
    "introspection_url": "https://idp.example.com/oauth2/introspect",
    "client_id": "agentlink",
    "client_secret": "********",
    "role_claim": "groups",                     // 缺省 "role"
    "role_map": {
      "agentlink-admins": "admin",
      "agentlink-ops": "operator",
      "agentlink-viewers": "viewer"
    },
    "default_role": null,                       // 缺省 null=拒绝；不得为 admin
    "namespace_claim": "namespace",             // 可选；多租户模式开启
    "cache_seconds": 30,                        // 1-3600
    "timeout_seconds": 3                        // 1-30
  }
}
```

- `X-Auth-Token: <token>` 与 `Authorization: Bearer <token>` 都接受；两者同时
  出现时 `X-Auth-Token` 优先。静态 token 也支持 Bearer（本包统一）。
- `role_map` 非空时，claim 值必须命中映射；claim 为数组时按顺序取第一个
  可识别角色。`role_map` 为空时直接把 claim 值当角色名
  （`admin/operator/viewer/executor`，大小写不敏感）。
- `default_role` 只允许 `operator/viewer/executor`；缺失/未命中时兜底。
  多租户模式下非 Admin 仍必须带 namespace。
- `namespace_claim` 存在时：
  - 非 Admin token 必须有该 claim，值 `[A-Za-z0-9_.-]{1,64}` 且非 `*`；
  - Admin token **不得**带该 claim（全局治理与租户绑定互斥，防止越权）；
  - claim 缺失的 Admin 仍为全局 Admin。
- `introspection_url` 生产必须 `https://`；`http://` 仅允许
  `127.0.0.1` / `localhost` / `[::1]`（本地 mock/开发），避免 client_secret
  与 bearer token 明文过网。
- 配置校验在 `Config::validate`：启用时必须给 URL/client_id/client_secret、
  合法角色映射、缓存/超时区间；关闭态完全不校验（旧配置零影响）。

## 2. 请求流程

```
请求（/v1/* 除公开路径）
  ├─ 剥除客户端伪造的 X-Agentlink-Oidc-Role / X-Agentlink-Oidc-Namespace
  ├─ token 是 auth.tokens 或 local_api.token？ → 直接放行（静态路径）
  ├─ OIDC 关闭？ → 直接放行（旧行为）
  ├─ 缓存命中（sha256(token), TTL）？ → 注入可信角色/namespace
  ├─ POST introspection_url（Basic client_id:client_secret,
  │    form token/token_type_hint=access_token, 超时）
  │    ├─ 非 2xx / 超时 / active!=true / 角色不识别 / namespace 非法
  │    │    → 401（不缓存失败；审计 auth.oidc_reject）
  │    └─ 成功 → 写缓存，注入内部头，进入 handler
  └─ handler 的 authorized_role/token_namespace 读注入头
```

- 公开路径不触发 introspection：`/v1/health`、`/web`、`/v1/web`、
  `/v1/starmap`、`/web/setup`、`/v1/ws`、`/peer/*`。
- 内部头只在中间件校验成功后写入；入口先剥除同名客户端头，防伪造。
- 401 响应不向客户端泄露 IdP 错误细节；审计 `auth.oidc_reject` 只记
  `reason`（截断 200 字符）与 token sha256 前 12 位，不记原始 token。
- 成功结果缓存 key 为 sha256(token)，内存不保存原始 token；重启清空。
- 角色/namespace 注入后复用现有 RBAC 与 namespace scope：
  Operator 仍不能读 `/v1/mesh/status|quota|metrics|config`；namespace 绑定
  token 的全局 history/events/files/metrics 仍 403。

## 5. 边界与残留

1. **不是 JWT 本地验签**：每个未知 token 需要一次 introspection（成功缓存）；
   IdP 故障时新 token 全部 401，已缓存 token 在 TTL 内继续可用（最长
   `cache_seconds`=3600s）。没有离线公钥验签能力。
2. **吊销延迟**：IdP 吊销 token 后，本节点最长延迟 `cache_seconds` 才重新
   自省；对安全敏感部署请设 5-30s。缓存是进程内、不跨节点共享。
3. **无负缓存**：随机构造 token 会持续打 IdP；应在反向代理/网关做入口限流。
   失败不缓存是为了避免把 IdP 临时故障固化。
4. **只消费 active/role/namespace**：`aud`/`iss`/`exp`/`nbf` 由 IdP
   introspection 判定；本节点不再校验。必须保护 client_secret 与
   introspection 链路（https）。
5. **浏览器/WS 未接 OIDC**：`/v1/ws` 仍只接受 `local_api.token` 查询参数
   （避免 token 进 URL 日志）；Web UI 登录仍是本地 token。OIDC 客户端请用
   `Authorization: Bearer` 调 REST。
6. **配置不热加载**：`PUT /v1/config` 只更新身份/日志等子集；`auth.oidc`
   变更需重启（与多数 security 段一致）。
7. **只支持 client_secret_basic**：不支持 mTLS client auth、
   `private_key_jwt`、JWT bearer assertion。
8. **namespace_claim 是全局开关**：不能按 IdP/租户选择不同 claim；非 Admin
   漏带 claim 一律拒绝（宁失败不放权）。没有 namespace 级 Admin 角色。
9. **角色映射是精确匹配**：不支持组层级/通配符；IdP 组名变更需改
   `role_map` 并重启。
10. **`default_role` 是逃生门**：只允许非 Admin；仍建议保持 `null`，靠
    显式 claim 映射，避免 IdP 配错时静默放行。
11. **`X-Auth-Token` 优先于 `Authorization`**：两者同时出现时以 X 为准；
    网关应剥离客户端自带的这两个头，避免歧义。
12. **审计开关**：`auth.oidc_reject` 仅在 `security.audit.enabled=true` 时
    入不可变链；关闭态仍打 401，但无审计记录。
