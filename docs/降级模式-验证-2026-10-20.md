# 降级模式（read-only / standalone）验证（2026-10-20，v0.7 §6.3）

路线图 v0.7：「降级：控制面故障 read-only 模式；工作节点本地队列自治 Standalone」。
本包把「降级」做成**显式、可观测、可运行时切换**的两种状态：

- **read_only（维护只读）**：拒绝新工作/治理写面，读面与在途任务收敛照常；
  `POST /v1/mesh/mode` 运行时进出（该端点自身不被拦截）。
- **standalone（本地自治）**：连续无直连对端达到阈值自动标记；本地队列照常
  调度执行，对端恢复自动回 `normal`。

缺省 `mesh.degraded{read_only=false, standalone_after_seconds=0}`：两种模式都不
生效，调度/API 行为零变化。

## 1. 配置与端点

```jsonc
"mesh": {
  "degraded": {
    "read_only": false,              // 启动初值（运行时可切）
    "standalone_after_seconds": 0    // 0=不自动判定；>0 为静默阈值
  }
}
```

| 端点 | 角色 | 说明 |
|---|---|---|
| `GET /v1/mesh/mode` | Admin/Operator/Viewer | `{mode, read_only, standalone_after_seconds, peers_online, peer_silence_seconds}` |
| `POST /v1/mesh/mode` | **Admin** | `{"mode":"normal"｜"read_only"}`；`standalone` 为自动判定，手工设置 400 |
| `GET /v1/status` | 读面 | 加性字段 `mode` / `read_only` |
| `GET /v1/mesh/status` | Admin | 加性字段 `mode` / `standalone_after_seconds` |

只读下的写面拒绝清单（统一 503 `{error:"read_only"}`）：

- `POST /v1/tasks`、`POST /v1/tasks/{id}/cancel`、`DELETE /v1/tasks/{id}`
- `POST/DELETE /v1/agents`（注册/注销）
- `PUT /v1/config`
- **不拦** `/v1/send`（在途执行方的 progress/succeeded/failed 必须能回传）、
  `/v1/lockdown`（安全动作）、`POST /v1/mesh/mode`（退出只读的唯一入口）。

## 2. 状态机与语义

```
                 POST mode=read_only
   normal ─────────────────────────────► read_only
     ▲   ◄─────────────────────────────      │
     │        POST mode=normal               │ 只读优先级最高
     │                                        ▼
     │        无直连对端 ≥ 阈值            (read_only)
     └──────────── standalone ◄──────────────┘
                  对端恢复
```

- **只读优先级最高**：`read_only` 期间即使无对端，对外仍报 `read_only`；退出后
  若静默已超阈值立即落到 `standalone`。
- **standalone 判定**：`peers_online == 0` 且距最后一次直连对端连接/断开
  ≥ `standalone_after_seconds`。计时起点是进程启动（从未连过对端也按静默算）。
  经中继/目录学到的远端**不**算直连对端（spine 不可达即视为控制面不可达）。
- **本地自治**：standalone 只做状态标记，不改变调度——引擎本来就只向在线
  agent 派发，无对端时本地队列继续收敛；新本地任务仍可提交。
- **模式转换审计**：引擎 tick 检测变化 → `mode.change`（actor=`engine`，
  from/to/peers_online）+ webhook `node_degraded`（进入非 normal）/
  `node_recovered`（回 normal）。
- **人工切换审计**：`POST /v1/mesh/mode` 写 `mode.set`（actor=角色，
  from/to/read_only）。两条记录语义不同：一条“谁按了开关”，一条“状态事实”。

## 5. 边界与残留（后续波次）

1. **只读不冻结引擎**：已接受任务继续收敛（可用性优先）。若维护窗口需要“连引擎
   也停”，用 `lockdown`（拦业务帧）或停进程；两者语义不同，文档已区分。
2. **standalone 只是状态标记**：本地自治是既有能力（引擎只向在线 agent 派发），
   没有新增离线队列/领导者选举；跨节点队列的“接管”仍属 Raft/HA 范畴。
3. **自动只读未实现**：无法可靠区分“控制面故障”与“网络分区”，自动进只读可能
   把可用集群锁死；当前由运维/外部策略调用 `POST /v1/mesh/mode` 决定。
4. **运行时只读不持久化**：重启回到配置初值（防止一次维护忘记退出成为永久只读）；
   需要持久只读请改配置。
5. **standalone 只看直连对端**：经中继的叶子在 spine 失联后都会各自进 standalone；
   这是刻意口径（relay 可达 ≠ 控制面可达），但多级拓扑下会同时大面积标记。
6. **webhook 无额外冷却**：只在模式转换时各发一次；抖动（对端反复上下线）会对应
   多次事件，外部告警需自行聚合。
