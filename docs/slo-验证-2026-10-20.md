# SLO 告警 + 历史基线异常检测验证（2026-10-20，v0.7 §7.2）

路线图 v0.7：「SLO 告警 + 历史基线异常检测（耗时 +30% 类趋势）」。本包交付
**单节点观测闭环**：任务终态样本 → 窗口统计（P50/P95/P99/错误率）→ 阈值告警
→ webhook `slo_alert`；同时用慢速 EWMA 维护「历史基线」，窗口 P50 超过基线
`baseline_ratio`（缺省 1.3）即判定漂移异常，基线跨重启持久化。

纯观测：不改变调度、投递、任务协议；`enabled=false`（缺省）时零采集、零告警。

## 1. 配置

```jsonc
"mesh": {
  "enabled": true,
  "engine": {
    "slo": {
      "enabled": true,
      "window_seconds": 300,   // 统计窗口
      "min_samples": 20,       // 不足只展示、不判阈值
      "p99_ms": 5000,          // 耗时 P99 上限
      "error_rate": 0.05,      // failed+declined+expired / 样本
      "queue_depth": 500,      // pending 队列上限
      "baseline_ratio": 1.3,   // 历史基线漂移阈值（+30%）
      "cooldown_seconds": 60   // 同类告警冷却
    }
  }
},
"webhook": { "url": "http://…", "events": "slo_alert" }
```

`GET /v1/mesh/slo`（Admin/Operator/Viewer 只读）返回窗口统计、基线、漂移比、
当前 active 告警与最近 20 条告警；mesh 关闭时返回同形状 `enabled=false`。

## 2. 语义

| 项 | 口径 |
|---|---|
| 样本 | 引擎观测到终态的**非预热池**任务；耗时为「首次入表/派发 → 终态」（单调钟，含排队与重试） |
| 窗口 | `window_seconds` 内样本，上限 4096 条；分位用 nearest-rank |
| 错误率 | `failed + declined + expired` / 样本数（cancelled 不算错误；预热池任务不计入） |
| 历史基线 | 全部历史样本的 EWMA（alpha=0.01），持久化到 `<data_dir>/slo_baseline.json`（60s 节流、临时文件 + rename 原子替换） |
| 漂移异常 | 窗口 P50 / 基线 > `baseline_ratio`（缺省 +30%） |
| 告警 | 四类：`p99` / `error_rate` / `baseline_drift` / `queue_depth`；同类按 `cooldown_seconds` 冷却；`tracing::warn` + webhook `slo_alert`（payload 带 kind/value/threshold/at/queue_depth/running） |
| 评估节奏 | 每秒一次（引擎 200ms tick 内节流），窗口裁剪 + 排序成本有界 |
| 缺省 | `enabled=false`：不采集、不初始化观察表、`/v1/mesh/slo` 纯静态视图；调度热路径只多一次空 map 判断 |

## 5. 边界与残留（后续波次）

1. **无跨节点聚合**：SLO 是每节点本地视图；集群级 SLO 需要控制面汇总
   （可复用 `node_dir`/控制面验签通道）。
2. **基线只持久化 EWMA**，窗口样本与 `first_seen` 观察表不落盘：重启后进行中
   任务不产生耗时样本（终态仍会更新状态机）；基线本身跨重启保留。
3. **漂移会被基线缓慢吸收**：持续回归约数十个样本后基线抬升、告警自然消退；
   若需长报警应配合外部告警系统对历史告警做聚合。
4. **预热池任务不计入**（避免 keep-warm 稀释业务耗时）；`cancelled` 计为成功侧。
5. **webhook 只有冷却、无 ack/重试语义扩展**：沿用既有 webhook 客户端
   （超时/重试配置同其它事件）；持续告警依赖冷却周期重复外发。
6. `/web` 未加 SLO 面板（当前 API/CLI 可查）；UI 留待后续。
