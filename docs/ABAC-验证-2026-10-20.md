# ABAC 策略引擎验证（2026-10-20，v0.7 §4.2 第一波）

路线图 v0.7：「ABAC 策略引擎（label × node 属性 allow/deny，如 finance-data
禁入低安全级节点）+ namespace 多租户」。本包交付**标签级 ABAC 调度过滤**，
namespace 多租户留待下一波。

缺省 `security.abac.enabled=false`：不读规则、不过滤，调度行为与之前完全一致。

## 1. 配置

```jsonc
"security": {
  "abac": {
    "enabled": true,
    "rules": [
      { "name": "finance-not-low", "effect": "deny",
        "task_labels": { "data": "finance" },
        "node_tags": ["zone:low"] },
      { "name": "secret-high-only", "effect": "allow",
        "task_labels": { "class": "secret" },
        "node_tags": ["zone:high"] }
    ]
  }
}
```

- `task_labels`：任务 `spec.labels` 的**全部** k=v 命中才 applicable；只认字符串值。
- `node_tags`：节点 `tags` 必须**全部**具备；空数组 = 对所有节点生效。
- `effect="deny"`：applicable 且标签命中 → 拒绝该候选，**deny 优先**。
- `effect="allow"`：applicable 时至少要有一条 allow 规则标签命中，否则拒绝
  （只约束命中其 `task_labels` 的任务；不相关任务不受影响）。
- 无规则 / 未启用 → 放行。
- 标签写入：任务提交时在 JSON 顶层带 `"labels": {"data":"finance"}` 原样入库；
  节点标签是本机 `tags` 配置（`"tags": ["zone:low"]`）。

## 2. 调度链路

```
POST /v1/tasks {labels:{data:finance}}
        │  TaskRecord.spec（原文）
        ▼
Engine tick → Scheduler::schedule_batch
        ├─ requires ⊆ agent.capabilities
        ├─ constraints.exclude_tags
        ├─ ABAC: evaluate(abac, spec, node_tags[agent.node_id])
        └─ 打分/bin-pack → task_spec
```

- 远端节点 tags 经 `agents_update` 随 agent 表同步（payload 加性字段 `tags`），
  Router 存 `peer_tags`，引擎每拍构建 `node_tags = peer_tags + local_tags`。
  中继拓扑下 tags 随既有 `agents_update` 中继一起传播。
- 被策略挡住的任务**保持 pending**（不失败、不消耗 attempts）；节点补上正确
  标签后下一拍自然被调度。
- `GET /v1/mesh/status` 的 `engine.abac` 暴露 `{enabled, rules:[name…]}`。

## 5. 边界与残留（后续波次）

1. **标签自证**：节点 tags 由节点自己在 `agents_update` 中声明，没有签名绑定/
   硬件证明；恶意节点可自称 `zone:high` 绕过 allow。后续可把 tags 纳入准入
   证明（attestation）或由控制面签发。
2. **旧节点无 tags**：deny 规则不命中（fail-open），allow 规则会拒绝。混合版本
   集群里对敏感任务应使用 allow 规则，并先完成全量升级。
3. **仅静态标签**：规则基于任务 `spec.labels` 与节点配置 `tags`，不支持运行态
   属性（CPU/内存/地域/时间）或嵌套对象；值只认字符串。
4. **无 namespace/租户隔离**：本波只是调度过滤，没有按 namespace 分表、分
   token、分配额；roadmap §4.2 的多租户部分留待下一波。
5. **策略变更需重启**：`PUT /v1/config` 的子集不含 abac，改策略要编辑配置文件
   重启；运行中无 reload。改动会经 `config.update` 审计（若审计开启）。
6. **拒绝无显式事件**：被挡任务只表现为 pending，`/v1/mesh/status` 能看到规则；
   未加 `abac_denied` 计数/审计（避免每拍刷屏）。排障需对照任务 labels 与节点 tags。
7. **空 task_labels 的 allow 规则是全局白名单**：要求所有任务都落带指定 tag 的
   节点；这是刻意语义，配置时需注意。
