# 消息组 thread 字段验证记录（第十五轮 R2）

日期：2026-10-18 ｜ 分支：`feat/v058-thread`（基于 main=v0.5.7）｜ 状态：全部通过

## 1. 字段规格

`thread` 为 Envelope 顶层可选字段（`src/proto.rs`），与 `reply_to`/`trace_id` 同型：

```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub thread: Option<String>,
```

- 语义：显式线程键。同一 `thread` 字符串的消息即一个「消息组」，星图整组收成一张话题卡，话题名直接用 thread 字符串（截断 26 字符）。
- 落账：`HistoryEntry`（`src/router.rs`）增 `#[serde(default)] pub thread: Option<String>`，本地发送与远程入站两处落账均携带；`/v1/history/search` 返回项自然带出 `thread` 键。
- HTTP：`POST /v1/send` 请求体接受 `"thread": "<组名>"`（`src/api.rs` SendRequest；纯空白按未填处理）。
- CLI：`agentlink task submit --thread <组名>`（`src/cli.rs`，随 POST body 发送）。
- 控制台：发送表单新增「消息组」文本输入（`grp2`，placeholder 示例组名），doSendAll 随 body 携带 `thread`。
- 星图：`web/starmap.html` buildTopics 归组键 `e.thread || 链根msg_id`；有 thread 时组 id 为 `t:` + `encodeURIComponent(thread)`（防与 msg_id 相撞及 attribute 注入），组名即 thread 文本。只改 buildTopics，连线渲染区（renderLinks/flyIn/poll fresh）未动。

## 2. 兼容策略

- 旧请求/旧 JSON 不含 `thread` → serde default 为 `None`，行为回退旧 reply_to 链根归组，星图既有分组不变。
- 旧 `history.jsonl` 行（无 `thread` 键）→ 读取侧 default `None`，加载不炸；启动恢复进内存 ring 同样兼容（冒烟 S3 实测：v0.4 风格无 thread 行重启后可检索、方向不变）。
- 混版本转发：旧（未升级）节点收到带 `thread` 的帧可正常转发/落账，但旧节点用自己的 Envelope 结构重新序列化，**转发途中 `thread` 键会丢失**（未知字段丢弃属预期）。因此滚动升级期间以旧节点为中转的链路会退化为 reply_to 归组。**结论：编排方 B 节点先升级到 ≥v0.5.8 即可**——编排方直发/直收的消息 thread 全程保留，星图按组归并在编排方本地立即生效。
- wire 上不带 `thread` 时 `skip_serializing_if` 省略该键，帧尺寸对旧节点零增量。
