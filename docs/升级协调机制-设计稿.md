# AgentLink 版本升级协调机制 · 设计稿 v1

（发起方：主节点 4f793d7cd6fc / study=Hermes；评审人：主人拍板）

## 一、目标
1. 新版本稳定后，由发起方一键把目标机器（含本机）的 AgentLink 升级到新版
2. 升级前：预告 → 该机所有 agent 准备 → 报备就绪 → 齐了才动手
3. 升级前备份旧版本，失败自动回滚
4. 版本全过程留痕，不丢信息

## 二、总原则
- **不改 AgentLink Rust 内核**。协调全部走业务层消息（text/send + 约定 payload），符合"小而稳"定位；消息协议文档化进 docs/。
- **角色**：
  - 发起方：本机 study（Hermes 网关，就是我）
  - 执行者：目标机上的常驻守护进程。7 号机 = liteguard daemon.py（它已有"系统操作"能力，零新增部署）；本机 = daemon 同款角色
  - 准备方：目标机上除执行者外的所有 agent（fanbot、lunaloo、A-Study…）

## 三、消息协议（5 种 payload.topic）
1. `upgrade_notice`  执行者→本机全体（广播 to=目标node 不带 to_agent）
   {old, new, eta(ISO时刻), ready_deadline(秒), backup_path, zip_sha256}
   - 提前量默认 **5 分钟**（eta = now+300s），deadline 默认 **120 秒**
2. `upgrade_ready` / `upgrade_declined`  各 agent →to_agent=执行者
   ready: {agent, drained:true}  declined: {agent, reason, need_extra_seconds}
   - "准备"= 暂停发大件/批量消息、消费完自己收件箱、持久化自有状态
3. `upgrade_go` / `upgrade_abort`  发起方确认齐备（或 deadline 决策）→执行者+全体
4. `upgrade_done` {new_version, health_ok, elapsed} / `upgrade_rolled_back` {reason, restored}
   执行者 →发起方 + 广播全体
5. 全程 msg 走普通点对点 at-least-once（有 ACK/重试），广播仅作旁路通知

## 四、执行者流程（daemon 收 go 后）
1. 收 zip（文件通道，SHA-256 已在信封里）
2. 备份：当前 exe + agentlink.json → `backups\v<旧版>_<时间戳>\`
3. 解压 → 校验 sha256 == notice 里的值（防半包）
4. taskkill 旧进程 → 覆盖二进制 → 启动.bat 拉起
5. 轮询 health：version==new 且 ok → 报 done
6. **失败自动回滚**：30 秒内 health 不达预期 → 还原备份二进制并启动 → 报 rolled_back（回滚后再校验一次）
7. 重启前后 agentlink.json 不动（node_id/token 不变，其他机器的连接自动重连回来）

## 五、发起方编排流程（我这边，一次脚本化）
1. git 确认 tag+dist zip 存在、版本已推远端（版本管理前置）
2. send-file 把 zip 发给目标机执行者（带 to_agent 定向）
3. 广播 upgrade_notice → 收 ready 报备；deadline 内：
   - 全 ready → go
   - 有人 declined 且追加时间可接受 → 顺延（最多一次）
   - 超时未报备 → 视为就绪（尽力原则，agent 掉线本来收不到消息）
4. 发 go → 盯 done/rolled_back → 向主人汇报结果 + 记台账
5. 升级完成后：GET 各机 /v1/health 核对 fleet 版本表，确认无半新半旧异常组合

## 六、本机（主节点）自身升级
同协议同流程，执行者是本机 daemon；特殊点：
- 发起方 study 自己就挂在将被重启的节点上——**重启前把"进行中升级"状态落盘**（台账条目 status=in_progress），网关重连后自动续跑第 5 步核对
- 顺序建议：先升远端机，验证无误后最后升本机

## 七、版本管理（不丢信息）
- 既有：git commit+tag、origin push、dist 内 exe/linux/zip
- 新增：`upgrade-ledger.json`（追加式，每台被升机器 data_dir 一份 + 发起方 git 仓库同步一份双保险）
  条目：{time, node, old→new, executor, sha256, backup_path, result:done/rolled_back, agents_reported:[…]}
- 发起方维护 fleet 版本表（每轮升级前后各采一次 /v1/health）
- **回滚保留策略**：backups 只留最近 2 个版本（体积考虑）
