# v0.6 P1 mTLS — 实现与验证（2026-10-19）

对应路线图 v0.6 §4.1：**可选 mTLS：内置 CA 一键签发 + 24h 轮转（LAN 默认关闭、一键开启）**。

两波交付：
- **第一波 证书内核**：内置 CA 一键签发/复用/轮转 + 指纹 + `agentlink mtls` CLI。
- **第二波 节点间 TLS 传输**：独立 TLS 监听端口 + 发现广播 + `wss://` 拨号 +
  双向 TLS（客户端证书校验）+ 文件通道同步加密。

默认关闭时对现网/本地 API **零行为变化**（`/v1/health` features 逐字符不变、
本地 API 仍明文 HTTP、老节点混跑不破）。

## 1. 存储与产物

默认落在 `<data_dir>/mtls/`（`mtls.ca_cert`/`mtls.ca_key` 可改写 CA 路径）：

| 文件 | 内容 |
|---|---|
| `ca.pem` / `ca.key` | 集群根 CA（ECDSA P-256，自签，10 年） |
| `node.pem` / `node.key` | 本机节点证书（由 CA 签发，`ServerAuth+ClientAuth`）+ 私钥 |
| `node.expiry` | 节点证书到期时间（Unix 秒），用于轮转判定 |

节点证书的 SAN 含 `localhost` / `127.0.0.1` / `::1` / 主机名 / 本机全部网卡 IP，
使对端按 **IP 拨号**时标准 rustls 校验器即可通过名称校验（无需自写「跳过域名」
的危险校验器）。Unix 上私钥尽力收紧 `0600`。

**集群共享 CA**：一个集群必须共用同一 CA（CA 证书 + 私钥），各节点用同一 CA
**各自签发自己的节点证书**。做法：把 `mtls.ca_cert`/`mtls.ca_key` 指向同一份
文件（例如共享目录），或把首节点的 `mtls/` 目录分发给其他节点。这与
`cluster_token` 的分享语义一致（信任域密钥，离线自托管）。冒烟 S0 即演示了
「共享 CA 就绪 → 两节点互信」。

## 2. 设计取舍：不引入 X.509 解析依赖

CA 仅作「签发者」使用——rcgen 的 `serialize_pem_with_signer` 只读取 CA 的
**issuer DN + 签名算法 + 私钥**（本模块自持常量 + 落盘私钥），故重签发节点
证书无需回读解析 CA 证书；到期时间单独落 `node.expiry`。只依赖 `rcgen`
（默认 `pem` feature），不启用 `x509-parser`。

## 3. 生成与轮转语义（`src/mtls.rs`）

- `load_or_create`：CA 可读则复用，否则新生成整条链；节点证书在轮转窗口外
  则复用，否则用现有 CA 重签（**CA 不变**）；节点证书缺失/损坏也沿用现有 CA。
- 轮转判定：距到期不足 `cert_rotate_interval_seconds`（默认 6h）或已过期即重签。
- `rotate_node_cert()`：用现有 CA 立即重签并落盘（CA 指纹不变）。
- 默认：`enabled=false`、`cert_ttl_days=1`（24h）、`cert_rotate_interval_seconds=21600`、
  `listen_port=None`（= `listen_port + 1`）。`MtlsConfig` 手写 `Default`。

## 4. CLI 一键启用（`agentlink mtls`）

```bash
agentlink mtls              # 等价 --show：打印状态/路径/指纹/到期
agentlink mtls --enable     # 生成/加载证书并把 mtls.enabled 置 true（一键开启）
agentlink mtls --disable    # 写回 enabled=false（保留证书文件）
agentlink mtls --rotate     # 立即轮转节点证书（CA 不变）
```

## 5. 节点间 TLS 传输（第二波）

- **独立 TLS 监听**：`mtls.enabled=true` 时在 `0.0.0.0:<mtls.listen_port>`
  （缺省 `listen_port + 1`）额外起一个 axum-server/rustls 监听，**只**挂
  `/peer/ws` 与 `/peer/file/ws`。本地 API 与 `/web` 仍在 `bind` 上走明文 HTTP，
  本地客户端（curl/浏览器/CLI/老 agent）不受影响。
- **服务端**：`WebPkiClientVerifier`（信任锚 = 本集群 CA）+ 本机节点证书 ⇒ 要求
  并校验客户端证书（真双向 TLS）。
- **客户端**：只信任本集群 CA + 出示本机节点证书（`ClientConfig::with_client_auth_cert`）。
- **发现广播**：`DiscoveryMessage` 新增加性字段 `mtls_port`（老节点忽略）；开启
  mTLS 的节点据此广播 TLS 端口，对端按「同源 IP + TLS 端口」改走 `wss://`。
- **机会式升级**：仅当本节点开启 mTLS **且**对端广播了 mTLS 端点时才用 `wss://`，
  否则明文 `ws://`。混合版本/灰度期不断网（未支持 TLS 的对端仍明文）。
- **静态 peer**：`discovery.static_peers` 支持 `wss://host:port` / `mtls://host:port`
  前缀标记该端点为节点间 TLS 端点。
- **文件通道**：`open_file_ws` 按对端 mTLS 端点升级到 `wss://`，文件字节不再明文。
- 依赖：`rustls 0.23`（**ring** provider，禁 aws-lc-rs，避免 C/cmake，保
  windows-gnu 交叉编译与单二进制）+ `axum-server 0.7`（`tls-rustls-no-provider`）
  + `tokio-tungstenite` 开 `rustls-tls-webpki-roots`（自定义 CA 连接器）。

## 9. 边界与后续

- **弹性**：节点证书含全部网卡 IP；IP 变化由 24h 轮转自然刷新。IP 尚未刷新时
  机会式降级为明文（已文档化）。
- **CA 分发**：目前靠共享 `ca.pem`/`ca.key`（配置路径或目录拷贝）。后续可做
  「首节点一键广播 CA 证书、其余节点 `join` 时自动落地」的引导流程（CA 私钥
  是否下发需再拍板）。
- **强制模式**：当前为机会式（对端未支持 TLS 则明文）。若需「开启即拒绝明文」，
  后续在 `mtls` 增加 `require` 开关并在明文 peer 通道拒连。
