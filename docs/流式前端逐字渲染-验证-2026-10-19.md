# 流式结果前端逐字渲染验证（2026-10-19，v0.7）

路线图 v0.7：「流式结果前端逐字渲染（WS 通道已有，补 /web 侧）【§5.3】」。

## 1. 交付

`web/starmap.html`（单文件控制台，`/web` 与 `/v1/web` 同一页面）新增
**「任务流式视图」** 浮层面板：

- 输入 `task_id` → 订阅；任务帧按 `task_progress` 逐条落列表，终态结果
  **逐字**打屏（24ms/拍、每拍 2 字符，末尾 `▍` 光标；成功绿 / 失败红）；
- 数据面**复用页面既有的无 `client` 观察者 WS**（`/v1/ws`）——该连接语义为
  「可见本机全部事件含定向帧」（`handle_subscriber`：`client_id` 为空即观察者），
  因此无需给页面加第二条连接或额外权限；
- 逻辑与渲染分离：`alStreamInit / alStreamReduce / alStreamStep /
  alStreamResultText` 是**纯函数**（页面内 `AL-STREAM-BEGIN…END` 标记块），
  可被外部提取做单测；渲染只做 DOM 拼装。

## 2. 收敛语义（纯函数契约）

| 输入 | 行为 |
|---|---|
| 非本任务（`task_id` 不符）/ 无 topic | 忽略（`changed=false`） |
| `seq <= state.seq` | 忽略（幂等重放 / 乱序帧丢弃） |
| `task_accepted` / `task_progress` | 追加进度行（带 `stage`/`#seq`），推进 `seq` |
| `task_succeeded` | `done`，`buf = 结果文本`（对象 JSON 化）→ 逐字打屏 |
| `task_failed` / `task_declined` | `done+failed`，行内含 `error`/`reason` |
| `task_cancelled` / `task_rolled_back` | `done` |
| `alStreamStep(shown, target, n)` | 单调前进、永不越界；`n<=0` 兜底 1 |

## 4. 边界与残留

1. 未做真实浏览器渲染验证（无 headless 浏览器依赖）——用「页面真实函数 +
   真总线帧」组合覆盖逻辑与数据面；DOM 拼装属薄层（`stRender`）。
2. 逐字只作用于**终态结果**；进度行为即时上屏（避免刷屏）。若需进度文本也逐字，
   把 `buf` 改为进度累积即可（纯函数已支持）。
3. 观察者 WS 可见全部定向帧是既有语义（第十轮 R1 拍板），流式面板沿用；
   若未来收紧为「仅 admin token 可观察」，面板自动继承该约束。
