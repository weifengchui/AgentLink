# OIDC 第三波：IdP 兼容硬化（2026-10-20，v0.7.2 候选）

第二波（`docs/OIDC-JWT与浏览器登录-验证-2026-10-20.md`）打通了
RS256/JWKS 本地验签 + Authorization Code/PKCE 浏览器登录。真实企业 IdP
（Keycloak / Okta / Azure AD / 腾讯云 / 阿里云 / 自建 Keycloak 等）在落地时
还会撞上五类兼容问题，本包逐一补齐：

1. **签名算法**：只支持 RS256 时，用 ES256/EdDSA/PS256 的 IdP 直接 401；
2. **`at_hash` / `c_hash`**：hybrid 流程里 IdP 会带 code/access token 摘要，
   不校验等于把 code 替换攻击的门开着；
3. **`response_mode=form_post`**：部分 IdP（含部分国密/私有化部署）只支持表单
   回传，query 回传会被 IdP 拒绝；
4. **RP-initiated logout**：退出只清了本地 session，IdP 侧会话仍在，用户换
   浏览器仍是登录态；
5. **refresh token**：浏览器 session 到期后要重新走 IdP 登录，8 小时一次，
   现场演示/值班切换体验差。

仍然保持：单二进制、纯 Rust 依赖（新增 `p256`，复用 `ed25519-compact`，
无 C / openssl）、`auth.oidc.enabled=false` 时旧配置与静态 token 行为不变、
`auth.oidc.allowed_algs` 缺省 `["RS256"]` 时**第二波行为逐字不变**。

## 1. 算法白名单（`allowed_algs`）

```jsonc
"auth": { "oidc": {
  "allowed_algs": ["RS256", "PS256", "ES256", "EdDSA"]   // 缺省 ["RS256"]
}}
```

| alg | 密钥类型 | 摘要 | 备注 |
|---|---|---|---|
| `RS256` | RSA（≥2048 bit） | SHA-256 | 第二波默认，缺省即此 |
| `PS256` | RSA（≥2048 bit） | SHA-256 | RSA-PSS，salt 长度=摘要长度 |
| `ES256` | EC P-256 | SHA-256 | JWKS `kty=EC, crv=P-256` |
| `EdDSA` | OKP Ed25519 | SHA-512 | JWKS `kty=OKP, crv=Ed25519` |

铁律：

- `none` / `HS*` / `PS*`（非 PS256）/ `ES*`（非 ES256）**永不支持**；
- **算法必须与 JWK 类型匹配**（防 alg confusion）：RSA key 不能配 ES256 头，
  EC key 不能配 RS256 头；
- JWK 若显式声明 `alg`（如 `alg=RS256`），则该 key **只**接受该算法；
  未声明时按 `kty` 推断（RSA→RS256/PS256，EC P-256→ES256，OKP→EdDSA）；
- 无 `kid` 时，只有**唯一一把匹配该算法**的 key 才可使用；
- 弱密钥（RSA 模长 <2048 bit）、坐标不在曲线上的 EC key 一律跳过；
  整份 JWKS 一把可用 key 都没有 → fail-closed（401）。

JWKS 缓存、未知 kid 触发刷新（2s 节流）、拉取失败 fail-closed 的语义与
第二波一致，只是选 key 时多了一层「算法 × 类型」匹配。

## 2. `at_hash` / `c_hash`

- `c_hash`：授权响应（query 或 form_post）里带了就必须与 `code` 摘要一致，
  不一致直接 400（防 code 替换）。
- `at_hash`：ID token 里带了就必须与 `access_token` 摘要一致；带了
  `at_hash` 却没有 access token 同样 400。
- 摘要算法随 ID token 的 `alg`：RS/PS/ES256 → SHA-256，EdDSA → SHA-512；
  取摘要**左半部分**、base64url 无 padding（OIDC Core §3.3.2.11）。

`c_hash` 在验签前用 ID token header 的 `alg` 预校验（先失败早退出），
`at_hash` 用**验签后**的 `alg` 校验。

## 3. `response_mode=form_post`

```jsonc
"response_mode": "form_post"   // 缺省 "query"
```

- 授权请求会带上 `response_mode=form_post`；
- 回调端点同时接受 `GET`（query）与 `POST`
  （`application/x-www-form-urlencoded`），两种都可用；
- state cookie 属性随之切换：`query` → `SameSite=Lax`（https 时加 `Secure`）；
  `form_post` → `SameSite=None; Secure`（跨站 POST 必须 `SameSite=None`，
  且 `SameSite=None` 必须配 `Secure`；回环 http 下现代浏览器按 trustworthy
  origin 放行，生产环境请用 https）。

其余（一次性 state、5 分钟 TTL、HttpOnly state cookie 防登录 CSRF、只支持
query/form 回调、不接受 `//host` 跳转）语义不变。

## 4. RP-initiated logout

```jsonc
"end_session_endpoint": "https://idp.example.com/oauth2/logout",
"post_logout_redirect_uri": "/web"      // 可选：站内绝对路径或 https URL
```

- `POST /v1/auth/logout` 先销毁本地 session，响应里带
  `end_session_url`（含 `id_token_hint` + `client_id` +
  `post_logout_redirect_uri`）；
- Web UI 的「退出 SSO」拿到该地址后 302 跳到 IdP，IdP 侧会话一并失效，
  再回跳 `post_logout_redirect_uri`；
- `id_token_hint` 用的是**服务端内存**里的 ID token，绝不下发浏览器
  （浏览器只拿到 `al_sess_*`）；
- 未配置 `end_session_endpoint` 时行为与第二波一致（只清本地 session）。

## 5. refresh token 续期

- 授权码换 token 时若 IdP 返回 `refresh_token`，**只存服务端内存**
  （`Session` 结构），不下发浏览器；
- 新端点 `POST /v1/auth/oidc/refresh`：用服务端 refresh token 换新 ID
  token → 本地验签 → **原地延长**同一个 `al_sess_*`（浏览器 token 不变）；
- 角色 / namespace 在续期时**不允许被 IdP 改宽**（与原会话不一致直接拒绝）；
- session 过期后仍有 **15 分钟续期宽限窗**：期间 refresh 可用，过期即 401；
- Web UI 收到 401 会自动 `POST /v1/auth/oidc/refresh` 一次并重放原请求
  （失败才弹回 token 层）；
- IdP 不返回 refresh token 时该端点返回 409（`no refresh token`）。

要拿到 refresh token，IdP 侧通常需要 `scope` 含 `offline_access` 或
`prompt=consent`——把它加进 `auth.oidc.scopes` 即可。

## 6. 端点

| 端点 | 方法 | 说明 |
|---|---|---|
| `/v1/auth/oidc/status` | GET | 公开；新增 `allowed_algs` / `response_mode` / `rp_logout` |
| `/v1/auth/oidc/login` | GET | 302 到 IdP（带 PKCE / nonce / state / response_mode） |
| `/v1/auth/oidc/callback` | GET / POST | query 与 form_post 两种回传 |
| `/v1/auth/oidc/refresh` | POST | refresh 续期（浏览器 session 专用） |
| `/v1/auth/logout` | POST | 退出；新增 `end_session_url`（RP-initiated logout） |

## 8. 边界与残留

- **仍是单节点内存态**：浏览器 session / state / refresh token 都在本节点
  内存里，多副本部署需要粘性会话或外部 session store（与 v0.8 HA 议题绑定）。
- **refresh 宽限窗 15 分钟是写死的**，暂不可配；IdP 侧 refresh token 过期
  后会拿到 502，浏览器弹回 token 层重新登录。
- **`at_hash`/`c_hash` 只在 claim 存在时校验**（OIDC 允许纯 code flow 不带）。
- **不支持** `ES384`/`ES512`/`PS384`/`PS512`、`Ed25519` 以外的 EdDSA 曲线、
  `response_mode=fragment`、JWT 携带 `crit` 头。
- 未做 **RP-initiated logout 的 `state` 参数**回传校验（IdP 侧回跳参数透传）。
- 未做 **IdP 侧会话超时与本地 session 的联动**（本地 session 到期不会通知
  IdP 登出）。
- 上一波残留仍在：`refresh` 之外没有 `token` 端点、`client_secret` 只支持
  `client_secret_basic`、多租户模式下 IdP 必须把角色 claim 放进 ID token。
