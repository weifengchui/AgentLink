# Web 控制台需求台账 · 2026-10-16 第三轮

背景：0.4.17 交付后用户以测试样例实测，反馈 3 项。范围：web/starmap.html（悬停卡组）+ src/api.rs 与 starmap.html 的 agent 配色公式（三处统一）。

## R1 agent 配色按 agent_id 全局一致
- 现象：不同机器上同名 agent（如都叫 study）胶囊/卫星颜色不同，无法靠颜色识别 agent 身份。
- 根因：`agHue(n,a)=(nodeHue(n)+140+fnv(a)%100)%360`，色相锚在节点上，跨机必然不同。
- 修法：纯 agent_id 派生色相，手动配色覆盖键 `agent:node|id` 与 `node:id` 保留兼容；api.rs 与 starmap.html 两处公式逐字一致。
- 验收：测试节点注册跨节点同名 agent，对话行胶囊与星图卫星同色；改名不同 id 色不同。
- 状态：[x] 10-16 验收通过。最终公式升级为 fm32(fnv('|uo'+id))%360（murmur3 finalizer 提升散列均匀度；S=46+fm32(fnv('S|'+id))%28、L=56+fm32(fnv('L|'+id))%24；盐经全网真实 id 池搜索，agentlink/study/liteguard/webui 四色相两两间距≥60°）。浏览器实测：同名 agent 跨机同色、异 id 零同色对；api.rs 单一定义源与 starmap.html 公式逐字一致。

## R2 悬停消息组卡片紧跟光标
- 现象：悬停节点（站群）时卡组贴到站群侧边，离光标太远；agent 卫星同理按站侧排布。
- 根因：`posDwrap` 水平候选 = 站/卫星左右侧 `x±halfw+PAD+PW`，站群越宽越远。
- 修法：`reveal()` 时快照光标位置为锚点 `dwAnchor[k]`：水平 `x=an.x+20`（右侧放不下且左侧放得下才翻 `an.x-20-PW`，只判一次）；纵向卡组整体摆到光标右下 `top=an.y+14`，下方溢出翻 `an.y-14-cardH`，再视口钳位；删除站群侧向候选与障碍搜索。
- 验收：悬停站中心与悬停 agent 胶囊，卡组距光标 ≤ ~60px。
- 状态：[x] 10-16 验收通过。浏览器实测 agent 卡组（webui→study 3 卡）与站卡组（node 端点 2 卡）距光标均 24px，均不遮盖胶囊/站球本体与光标。

## R3 光标移动禁止卡片抖动
- 现象：光标在实体附近移动时卡组位置频繁跳动/闪。
- 根因：布局每次读实时 `CUR.y`（t0），5s 轮询重建与展开/收起重排都会按当时光标重算位置；左右候选随光标越过分界来回翻。
- 修法：锚点只在 `reveal()` 快照一次存 `dwAnchor[k]`，`layoutDeck/posDwrap` 一律读快照不读实时 CUR；左右翻转判定同样只发生在快照时刻；保留 140ms pointerleave tomb 与 600ms scheduleHide；`renderAllDecks`（轮询重建）后按快照原位重排。
- 验收：浏览器断言——reveal 后连续 dispatch 20 次 pointermove（同一实体上/附近），`dw.style.left/top` 字符串不变；卡组不覆盖光标落点。
- 状态：[x] 10-16 验收通过。浏览器断言：reveal 后连续 20 次 pointermove、renderAllDecks 轮询重建、展开卡组后再移 6 次，三种情形 left/top 字符串零变化；清理循环含 dwAnchor 重置防残留。


## R4 「暂停流入/恢复流入」按钮简洁化（用户 10-16 追加）
- 现象：按钮文案在两态间整句切换，视觉跳动、占位宽。
- 修法：文案恒为「流入」；仅暂停时在文字前加暂停图标「⏸︎流入」（.on 青色描边同步作状态提示）。
- 验收：默认文案「流入」；点击→「⏸︎流入」；再点→「流入」。
- 状态：[x] 10-16 浏览器实测：默认文案「流入」→点→「⏸︎流入」且 .on 高亮→再点回「流入」；按钮单行不换行。

## R5 悬停卡组预览=「收到的最后 1 条」；单向发送不成卡（用户 10-16 追加，确认项）
- 确认结论：「点卡片→弹窗含该实体在该话题的来往历史」v0.4.17 已实现（openG 按 to===k||f===k 双向过滤入左侧序列）。未达标的是另一半：卡片第二行取该实体该话题「最后一条」但收发混排，且实体只发未收的话题也会成卡。
- 修法：groupsFor 记 recv/lastRecv（to===k 才算收到），零收到的组剔除，按 lastRecv 时间倒序；卡片正文、第三行路由、「Nmin 前」全部以 lastRecv 为准；「N 条」= 该实体来往总条数，与弹窗序列同口径（弹窗链同步剔除已隐藏实体消息）。
- 验收：只发未收的主题在发送方悬停不出卡；多来回收发的卡预览=最后一条收到的正文；点卡弹窗列表含该话题双向全部消息。
- 状态：[x] 10-16 双节点 TC1/TC2 实测：a1 悬停仅出 TC1 卡（无卡给只发未收的 TC2），预览=最后收到「完成验收TC1」而非其自身发送；b1 卡预览=「继续推进TC1」（排除其后续发出的完成验收），TC2 单条成卡「1 条」；A@node 只发未收卡组为空；点卡弹窗 3/3 双向序列=收→发→收全量。
